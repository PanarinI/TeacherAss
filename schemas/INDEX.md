# Схемы TeacherAss — эссенц-модели для автора

Self-contained `.svg` — понимание из самого артефакта. Держать список свежим.

- `kompanion-uchitelya.svg` (2026-07-12) — сущность «ИИ-компаньон учителя с живой памятью»:
  тело Reachy + душа-методист + сердце-память · что помнит → что делает · ось *инструмент → компаньон*.
  Костяк заявки КИВО; показана автору в сессии рождения замысла.
- `2026-07-16-peresborka-koncept.svg` — **⚠ ЭСКИЗ, ЗАПАРКОВАН автором 07-16** («не строим, пока не
  выберем» — воронка метода: сперва полноценное исследование ниши, потом выбор, потом стройка).
  Хранит захваченные решения (диалог-бот · вилки), НЕ руководство к стройке. Содержание эскиза:
  душа = сценарий автора · взаимодействие = диалог-бот (модель diffit, решение автора 07-16, легаси-форма
  хоронится) · три несущих щели (методики-каркас · свой материал/фото · память класса) · table-stakes поля ·
  три жёлтые вилки-кнопки автора (форма CWS↔iOS↔веб · сегмент ESL↔все предметы · память в MVP↔v2) ·
  путь MVP → каналы (Custom GPT) → горизонт (Ричи, КИВО в2). Опирается на карту поля + досье app-studio.
- `2026-07-17-svedenie-tri-tela.svg` (2026-07-17) — **сведение сущности** («свести два TeacherAss», реш.
  автора): одна ДУША-инвариант (методист · живая память · материал из фото) → три ТЕЛА, разделённые
  по ЦЕЛИ на два лагеря: **КИВО-робот** (валидация · не про деньги · волна 2) ↔ **доход-софт** (iOS ↔ CWS).
  Читка: робот и софт не конкурируют (разные оси); реальная нерешённая развилка — ВНУТРИ доход-лагеря
  (iOS↔CWS) + вилки сегмента и памяти из эскиза. Снимает рассинхрон «двоения» app-studio↔капсула.
